6. PREGUNTAS QUE LE HICE PARA ENTENDER EL CODIGO
==================================================

P1) "Me podes explicar de que trata esto? No entendi nada el README."
    R: Es la agenda de un congreso (12 charlas, 2 dias) con tres pestanas: Programa,
    Mi agenda y Mesa. El README trae 4 reclamos: (41) sin senal debe mostrar lo guardado,
    (42) no perder las favoritas al actualizar, (43) recordar pestana, ficha y filtros
    aunque Android mate la app, (44) no descargar de mas.

P2) "Que es eso de Mesa? Como un tablero de pruebas? Como un servidor de mentira?"
    R: El servidor no es real: es una funcion dentro de la app (src/lab/servicio.ts) que
    ataja el pedido de axios, espera 1,4 segundos y contesta con uno de cuatro archivos
    JSON. La Mesa es el control remoto de ese servidor falso: elige que version contesta
    (v1 a v4), lo apaga para simular falta de senal, lo hace lento y cuenta los pedidos.
    Sirve para probar los 4 reclamos sin internet real.

P3) "Que seria que version del programa manda el servidor? El servidor es la API, el
    backend?"
    R: Si, el servidor es el backend y la app le habla por una API: GET /programa, que
    devuelve un JSON con la lista de charlas. "Programa" no es un programa de computadora:
    es la grilla de charlas del congreso. Cada vez que los organizadores la cambian es una
    version nueva: v1 la original, v2 la charla 11 cambia de titulo y sala, v3 se cancela
    la 11 y entra la 90, v4 grilla vacia. En el examen el backend es falso: el pedido lo
    contesta src/lab/servicio.ts leyendo uno de cuatro archivos JSON.

P4) "Que es una grilla?"
    R: La lista de charlas del congreso con su dia, hora y sala, como una grilla de
    horarios. En el codigo es una lista de fichas (cada ficha es una charla con id, title,
    day, time, room, speaker). Grilla, programa y edicion apuntan a lo mismo.

P5) "A que se refiere 'para que pedido sirve' en la tabla de la Mesa?"
    R: "Pedido" es cada reclamo numerado del README (41 a 44). La columna dice que reclamo
    se puede probar con cada boton de la Mesa. Ejemplo: los botones v1 a v4 sirven para
    probar el 42 (paso a v2 y miro si la favorita sigue) y el 41 (elijo v4 y miro si dice
    "sin charlas programadas"). La Mesa no arregla nada: sirve para comprobar.

P6) "La parte de 'como se prueba' del pedido 41 no la entendi. Explicala bien."
    R: Son los pasos a mano para comprobar el arreglo. Caso A (ya descargo y no hay senal):
    Mesa, servicio "no", Programa, Actualizar; la lista debe seguir con el cartel de datos
    guardados. Caso B (nunca descargo): se borran los datos con "adb shell pm clear" y se
    abre con el servidor apagado; debe salir el cartel y el boton Reintentar. Caso C
    (descargo cero charlas): Mesa v4, Actualizar; debe decir "sin charlas programadas" y
    seguir asi al reabrir sin senal. La clave: B y C tienen la lista vacia, pero en B nunca
    descargo y en C descargo cero charlas.
